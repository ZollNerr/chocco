# Light Watcher v2.0 — модернизация прошивки

Форк прошивки [Light_Watcher v1.6](https://github.com/Stanislav-developer/Light_Watcher) (ESP32-C3 + Telegram).
Прошивка: [`Light_Watcher_Firmware_v2.0/Light_Watcher_Firmware_v2.0.ino`](Light_Watcher_Firmware_v2.0/Light_Watcher_Firmware_v2.0.ino)

## 1. Что было не так в v1.6 (найденные проблемы)

| # | Проблема | Последствие | Решение в v2.0 |
|---|----------|-------------|----------------|
| 1 | Одно чтение АЦП без фильтра, жёсткий порог 3000 | Ложные «вимкнули/увімкнули» при скачках напряжения | Усреднение 16 замеров, гистерезис (3000/2700), антидребезг 3 с — всё настраивается |
| 2 | Сообщение «світло вимкнули» теряется, если Wi-Fi пропал (роутер обесточен одновременно) | Самое важное событие не доходит | Очередь из 12 событий с повторами раз в 15 с; время восстанавливается задним числом |
| 3 | При перезагрузке без интернета устройство уходит в режим настройки **навсегда** | Мониторинг перестаёт работать до ручного вмешательства | Портал только если конфиг ещё ни разу не сработал, и с таймаутом 5–10 мин |
| 4 | `/restart` и `/clear_data` перезагружают до отправки ответа | Владелец не получает подтверждения | Сначала ответ, потом перезагрузка |
| 5 | Нельзя подключиться к Wi-Fi без пароля | Открытые сети не работают | Пустой пароль разрешён |
| 6 | Неинициализированная переменная `attempts` в цикле синхронизации времени | Неопределённое поведение | Переписано |
| 7 | Летнее/зимнее время переключается вручную | Время в сообщениях сбивается дважды в год | POSIX TZ `EET-2EEST,M3.5.0/3,M10.5.0/4` — автоматически |
| 8 | Обрабатывается только последнее сообщение из очереди Telegram | Команды теряются | Обработка по offset |
| 9 | Отложенное сообщение отправляется в пустой `groupId` | Лишние ошибки | Проверка |
| 10 | Нет интеграций, кроме Telegram | Внешние системы не узнают о свете | HTTP API, Webhook, MQTT, Prometheus |

## 2. Варианты модернизации (от простого к сложному)

### Уровень A — надёжность (реализовано)
Гистерезис и антидребезг, очередь уведомлений, защита от «залипания» в портале, Wi‑Fi watchdog (через 10 минут без связи стек Wi‑Fi перезапускается), автоматический переход на летнее время.

### Уровень B — кастомизация (реализовано)
- **Шаблоны сообщений** с переменными `{time} {date} {datetime} {duration} {off_time} {count} {name}`
- **Имя устройства** (для нескольких адресов: «Дом», «Офис», «Склад»)
- **Пороги АЦП и антидребезг** — калибруются командой `/adc`, без перепрошивки
- **Тихие часы** — ночью уведомления приходят без звука
- **Часовой пояс** — любой POSIX TZ
- Всё это настраивается тремя способами: командами бота, через веб-страницу `/settings` или в портале при первой настройке

### Уровень C — внешние приложения (реализовано)
| Канал | Для чего | Как |
|-------|----------|-----|
| **HTTP JSON API** | Любые приложения, скрипты, виджеты | `GET http://lightwatcher.local/api/status` |
| **Webhook** | n8n, Make, Zapier, Node-RED, свой сервер, CRM | POST JSON на ваш URL при каждом событии |
| **MQTT + Home Assistant** | Умный дом, автоматизации | Устройство появляется в HA автоматически |
| **Prometheus `/metrics`** | Grafana, графики, алерты | Скрейп раз в 15–60 с |
| **Веб-панель** | Планшет на стене, телефон | `http://lightwatcher.local/` |

### Уровень D — следующие шаги (не реализовано, предложения)
1. **OTA-обновление по Wi‑Fi** — нужна схема разделов с OTA (сейчас «Huge APP No OTA»).
2. **Мониторинг заряда аккумулятора** — второй АЦП-вход через делитель: «батареи осталось ~40 мин».
3. **Три фазы** — 3 входа АЦП, уведомление «пропала фаза B». Полезно для частных домов и бизнеса.
4. **Подписка жильцов** — `/subscribe` для соседей вместо одной группы (сценарий ОСББ).
5. **Ежедневный отчёт** в 21:00: сколько было без света за день.
6. **Облачный агрегатор** — все устройства шлют webhook на один сервер → карта района/города, публичная страница «есть ли свет на ул. X», сравнение с графиками отключений.
7. **TLS с проверкой сертификата** Telegram вместо `setInsecure()`.

### Бизнес-взгляд
- **Для кого:** ОСББ и управляющие компании, офисы и магазины (холодильники, серверные), владельцы дач и сдаваемых квартир, фермы и теплицы, операторы связи и провайдеры (мониторинг узлов).
- **Боль:** «Нет света — я не знаю, сколько уже; включился ли генератор; не испортились ли продукты».
- **Монетизация:** готовое устройство + бесплатный бот; платная подписка на облачную панель с несколькими объектами, история, SLA-отчёты для арендаторов, интеграции с CRM и генераторами.
- **Отличие от конкурентов:** открытый API и MQTT — легко встраивается в чужие системы (B2B).

## 3. Команды Telegram-бота

**Для всех в группе:** `/light` (или фраза «Світло є чи нема?»), `/history`, `/stats`, `/id`.

**Только владелец:**

| Команда | Что делает |
|---------|------------|
| `/status` | Состояние: сеть, АЦП, Wi‑Fi, MQTT, очередь, аптайм |
| `/adc` | Текущее значение АЦП — для калибровки порогов |
| `/threshold 3000 2700` | Порог «свет есть» / «света нет» |
| `/debounce 3000` | Антидребезг в мс |
| `/quiet 23 7` / `/quiet off` | Тихие часы |
| `/name Дача` | Название в сообщениях и в Home Assistant |
| `/tz auto\|summer\|winter\|<POSIX>` | Часовой пояс |
| `/msg_off …` / `/msg_on …` / `… default` | Шаблоны сообщений (`\n` — перенос строки) |
| `/webhook URL` / `off` | HTTP-уведомления |
| `/mqtt host [port] [user] [pass]` / `off` | MQTT-брокер |
| `/web` | Адрес панели, логин и пароль настроек, список API |
| `/newkey` | Новый ключ API / пароль веб-настроек |
| `/test` | Тестовое уведомление во все каналы |
| `/clear_stats`, `/clear_data`, `/restart` | Обслуживание |

Пример шаблона:
```
/msg_off ⚫ {name}: світло зникло о {time}. Це вже {count}-е відключення.
/msg_on 💡 {name}: світло є з {time}\nНе було {duration} (з {off_time})
```

## 4. API для внешних приложений

Базовый адрес: `http://<IP>/` или `http://lightwatcher.local/` (IP пришлёт бот при старте или по `/web`).

### `GET /api/status`
```json
{
  "device": "Дача", "device_id": "a1b2c3", "version": "2.0",
  "power": false, "state": "off",
  "outage_started": 1763000025, "outage_duration_s": 1834,
  "outages_total": 17, "downtime_total_s": 152340,
  "downtime_24h_s": 9200, "downtime_7d_s": 51000,
  "adc": 812, "thr_on": 3000, "thr_off": 2700,
  "rssi": -61, "ip": "192.168.1.50", "uptime_s": 86400,
  "now": 1763001859, "time_synced": true, "queue": 0, "mqtt": true
}
```
Когда свет есть, вместо `outage_*` приходят `power_since` и `last_outage_duration_s`. CORS открыт — можно запрашивать прямо из браузера.

### Остальные эндпоинты
| Метод | Путь | Авторизация | Ответ |
|-------|------|-------------|-------|
| GET | `/` | — | Веб-панель (обновляется каждые 5 с) |
| GET | `/api/history` | — | Последние 30 отключений `[{off, on, duration_s, off_iso, on_iso}]` |
| GET | `/metrics` | — | Prometheus |
| GET | `/health` | — | `ON` / `OFF` (простой текст — удобно для Uptime Kuma, Zabbix) |
| GET/POST | `/settings` | Basic `admin:<ключ>` | Страница настроек |
| POST | `/api/test` | `X-Api-Key: <ключ>` | Тестовое уведомление |
| POST | `/api/restart` | `X-Api-Key: <ключ>` | Перезагрузка |

Эндпоинты чтения открыты **только в локальной сети**. Не пробрасывайте порт 80 в интернет — для удалённого доступа используйте Webhook, MQTT или VPN.

### Webhook (исходящий)
При каждом событии устройство отправляет `POST` на ваш URL, заголовок `X-LightWatcher-Event: power_off|power_on|boot|test`:
```json
{"event":"power_on","power":true,"device":"Дача","device_id":"a1b2c3",
 "ts":1763003770,"time":"2026-11-13T05:16:10+0200",
 "outage_duration_s":3745,"outage_started":"2026-11-13T04:13:45+0200",
 "device_rebooted":false,"outages_total":17,"delayed_s":0}
```
`delayed_s > 0` означает, что событие было в очереди, пока не было связи. Если ответ не 2xx — запрос повторяется.

### MQTT
| Топик | Данные |
|-------|--------|
| `lightwatcher/<id>/state` | `ON` / `OFF` (retained) |
| `lightwatcher/<id>/availability` | `online` / `offline` (LWT) |
| `lightwatcher/<id>/attributes` | JSON как в `/api/status`, раз в минуту и при событиях |
| `lightwatcher/<id>/cmd` | ← команды: `status`, `test`, `restart` |

В Home Assistant через MQTT discovery автоматически появляются сущности: «Електромережа» (binary_sensor, power), «Кількість відключень», «Поточне відключення», «Без світла за 24 год», «Рівень АЦП».

Примеры: [`examples/`](examples/) — автоматизации Home Assistant, Python-клиент и приёмник webhook.

## 5. Сборка и обновление с v1.6

1. Arduino IDE → Library Manager: **UniversalTelegramBot** 1.3.0, **ArduinoJson 7.x**, **PubSubClient** 2.8.
2. Настройки платы — как в v1.6 (ESP32C3 Dev Module, USB CDC On Boot: Enabled, Huge APP).
3. Прошить. Настройки Wi‑Fi и Telegram, а также счётчик отключений сохраняются: ключи Preferences совместимы с v1.6.
4. Написать боту `/adc` при свете и без него и выставить `/threshold` между этими значениями.

### Что проверено, а что нет
- ✅ Код проходит синтаксическую проверку g++ (C++17) с настоящим ArduinoJson 7.2 и заглушками API ESP32.
- ✅ Логика смоделирована на хосте: дребезг игнорируется, гистерезис держит состояние, событие при отсутствии Wi‑Fi ставится в очередь и уходит позже с пометкой, длительность и история считаются верно, тихие часы, восстановление после перезагрузки на разряженном аккумуляторе.
- ⚠️ **Не собрано тулчейном ESP32 и не проверено на железе.** Перед раскаткой: собрать в Arduino IDE, проверить на одном устройстве (вкл/выкл сеть, выключить роутер, перезагрузить без интернета).
