## 1. Что было не так в v1.6 (найденные проблемы)

| # | Проблема | Последствие | Решение в v2.x |
|---|----------|-------------|----------------|
| 1 | Одно чтение АЦП без фильтра, жёсткий порог 3000 | Ложные «вимкнули/увімкнули» при скачках напряжения | Усреднение 16 замеров, гистерезис (3000/2700), антидребезг 3 с — всё настраивается |
| 2 | Сообщение «світло вимкнули» теряется, если Wi-Fi пропал (роутер обесточен одновременно) | Самое важное событие не доходит | Очередь из 12 событий с повторами раз в 15 с; время восстанавливается задним числом |
| 3 | При перезагрузке без интернета устройство уходит в режим настройки **навсегда** | Мониторинг перестаёт работать до ручного вмешательства | Портал только если конфиг ещё ни разу не сработал, и с таймаутом 5–10 мин |
| 4 | `/restart` и `/clear_data` перезагружают до отправки ответа | Владелец не получает подтверждения | Сначала ответ, потом перезагрузка |
| 5 | Нельзя подключиться к Wi-Fi без пароля | Открытые сети не работают | Пустой пароль разрешён |
| 6 | Неинициализированная переменная `attempts` в цикле синхронизации времени | Неопределённое поведение | Переписано |
| 7 | Летнее/зимнее время переключается вручную | Время в сообщениях сбивается дважды в год | POSIX TZ `EET-2EEST,M3.5.0/3,M10.5.0/4` — автоматически |
| 8 | Обрабатывается только последнее сообщение из очереди Telegram | Команды теряются | Обработка по offset |
| 9 | Отложенное сообщение отправляется в пустой `groupId` | Лишние ошибки | Проверка |
| 10 | Нет интеграций, кроме Telegram | Внешние системы не узнают о свете | HTTP API, Webhook, MQTT, Prometheus |

## 2. Варианты модернизации (от простого к сложному)

### Уровень A — надёжность (реализовано)
Гистерезис и антидребезг, очередь уведомлений, защита от «залипания» в портале, Wi‑Fi watchdog (через 10 минут без связи стек Wi‑Fi перезапускается), автоматический переход на летнее время.

### Уровень B — кастомизация (реализовано)
- **Шаблоны сообщений** с переменными `{time} {date} {datetime} {duration} {off_time} {count} {name}`
- **Имя устройства** (для нескольких адресов: «Дом», «Офис», «Склад»)
- **Пороги АЦП и антидребезг** — калибруются командой `/adc`, без перепрошивки
- **Тихие часы** — ночью уведомления приходят без звука
- **Часовой пояс** — любой POSIX TZ
- Всё это настраивается тремя способами: командами бота, через веб-страницу `/settings` или в портале при первой настройке

### Уровень C — внешние приложения (реализовано)
| Канал | Для чего | Как |
|-------|----------|-----|
| **HTTP JSON API** | Любые приложения, скрипты, виджеты | `GET http://lightwatcher.local/api/status` |
| **Webhook** | n8n, Make, Zapier, Node-RED, свой сервер, CRM | POST JSON на ваш URL при каждом событии |
| **MQTT + Home Assistant** | Умный дом, автоматизации | Устройство появляется в HA автоматически |
| **Prometheus `/metrics`** | Grafana, графики, алерты | Скрейп раз в 15–60 с |
| **Веб-панель** | Планшет на стене, телефон | `http://lightwatcher.local/` |

### Уровень D — расширение (v2.1, реализовано)
| # | Функция | Подробности |
|---|---------|-------------|
| 1 | **Мониторинг аккумулятора** | Напряжение, %, прогноз «на сколько хватит», предупреждение 🪫 при низком заряде — [раздел 6](#6-аккумулятор-подключение-и-калибровка) |
| 2 | ~~Три фазы~~ | Не делали, нужно другое железо: три изолированных датчика |
| 3 | **Подписка жильцов** | `/subscribe` — открытая или с одобрения владельца, до 30 человек — [раздел 7](#7-подписка-жильцов) |
| 4 | **Сервер-агрегатор** | Карта и таблица объектов, SLA-отчёт, CSV, алерт «устройство пропало» — [раздел 9](#9-сервер-агрегатор-light-watcher-hub) |
| 5 | **OTA-обновление** | Через браузер, Arduino IDE по сети или `/update URL` в боте — [раздел 8](#8-ota-обновление-прошивки) |

### Ещё идеи (не реализовано)
- Три фазы — нужно отдельное железо: оптопары по фазам.
- Ежедневный отчёт в 21:00.
- TLS с проверкой сертификата Telegram.
- Отдельный Telegram-бот у сервера: «/svitlo вул. Хрещатик».

### Бизнес-взгляд
- **Для кого:** ОСББ и управляющие компании, офисы и магазины (холодильники, серверные), владельцы дач и сдаваемых квартир, фермы и теплицы, операторы связи и провайдеры (мониторинг узлов).
- **Боль:** «Нет света — я не знаю, сколько уже; включился ли генератор; не испортились ли продукты».
- **Монетизация:** готовое устройство + бесплатный бот; платная подписка на облачную панель с несколькими объектами, история, SLA-отчёты для арендаторов, интеграции с CRM и генераторами.
- **Отличие от конкурентов:** открытый API и MQTT — легко встраивается в чужие системы (B2B).

## 3. Команды Telegram-бота

**Для всех в группе и для подписчиков:** `/light` (или фраза «Світло є чи нема?»), `/history`, `/stats`, `/id`, `/subscribe`, `/unsubscribe`.

**Только владелец:**

| Команда | Что делает |
|---------|------------|
| `/status` | Состояние: сеть, АЦП, Wi‑Fi, MQTT, очередь, аптайм |
| `/adc` | Текущее значение АЦП — для калибровки порогов |
| `/threshold 3000 2700` | Порог «свет есть» / «света нет» |
| `/debounce 3000` | Антидребезг в мс |
| `/quiet 23 7` / `/quiet off` | Тихие часы |
| `/name Дача` | Название в сообщениях и в Home Assistant |
| `/tz auto\|summer\|winter\|<POSIX>` | Часовой пояс |
| `/msg_off …` / `/msg_on …` / `… default` | Шаблоны сообщений (`\n` — перенос строки) |
| `/webhook URL` / `off` | HTTP-уведомления |
| `/mqtt host [port] [user] [pass]` / `off` | MQTT-брокер |
| `/web` | Адрес панели, логин и пароль настроек, список API |
| `/newkey` | Новый ключ API / пароль веб-настроек |
| `/test` | Тестовое уведомление во все каналы |
| `/battery` | Заряд, напряжение, прогноз |
| `/bat_pin 4` / `off`, `/bat_div 2.0`, `/bat_cal 4.05`, `/bat_cells 1`, `/bat_low 20` | Настройка аккумулятора |
| `/subs`, `/subs open\|closed`, `/sub_add ID`, `/sub_del ID` | Управление подписчиками |
| `/heartbeat 10` / `0` | Пульс на webhook каждые N минут (нужен для сервера) |
| `/update URL` | Обновить прошивку по ссылке на `.bin` |
| `/clear_stats`, `/clear_data`, `/restart` | Обслуживание |

Пример шаблона:
```
/msg_off ⚫ {name}: світло зникло о {time}. Резерв {battery}. Це вже {count}-е відключення.
/msg_on 💡 {name}: світло є з {time}\nНе було {duration} (з {off_time})
```

## 4. API для внешних приложений

Базовый адрес: `http://<IP>/` или `http://lightwatcher.local/` (IP пришлёт бот при старте или по `/web`).

### `GET /api/status`
```json
{
  "device": "Дача", "device_id": "a1b2c3", "version": "2.0",
  "power": false, "state": "off",
  "outage_started": 1763000025, "outage_duration_s": 1834,
  "outages_total": 17, "downtime_total_s": 152340,
  "downtime_24h_s": 9200, "downtime_7d_s": 51000,
  "adc": 812, "thr_on": 3000, "thr_off": 2700,
  "rssi": -61, "ip": "192.168.1.50", "uptime_s": 86400,
  "now": 1763001859, "time_synced": true, "queue": 0, "mqtt": true
}
```
Когда свет есть, вместо `outage_*` приходят `power_since` и `last_outage_duration_s`. CORS открыт — можно запрашивать прямо из браузера.

### Остальные эндпоинты
| Метод | Путь | Авторизация | Ответ |
|-------|------|-------------|-------|
| GET | `/` | — | Веб-панель (обновляется каждые 5 с) |
| GET | `/api/history` | — | Последние 30 отключений `[{off, on, duration_s, off_iso, on_iso}]` |
| GET | `/metrics` | — | Prometheus |
| GET | `/health` | — | `ON` / `OFF` (простой текст — удобно для Uptime Kuma, Zabbix) |
| GET/POST | `/settings` | Basic `admin:<ключ>` | Страница настроек |
| POST | `/api/test` | `X-Api-Key: <ключ>` | Тестовое уведомление |
| POST | `/api/restart` | `X-Api-Key: <ключ>` | Перезагрузка |
| GET/POST | `/update` | Basic `admin:<ключ>` | Загрузка прошивки `.bin` через браузер |

Эндпоинты чтения открыты **только в локальной сети**. Не пробрасывайте порт 80 в интернет — для удалённого доступа используйте Webhook, MQTT или VPN.

### Webhook (исходящий)
При каждом событии устройство отправляет `POST` на ваш URL, заголовок `X-LightWatcher-Event: power_off|power_on|boot|test|battery_low|heartbeat`:
```json
{"event":"power_on","power":true,"device":"Дача","device_id":"a1b2c3",
 "ts":1763003770,"time":"2026-11-13T05:16:10+0200",
 "outage_duration_s":3745,"outage_started":"2026-11-13T04:13:45+0200",
 "device_rebooted":false,"outages_total":17,"delayed_s":0}
```
`delayed_s > 0` означает, что событие было в очереди, пока не было связи. Если ответ не 2xx — запрос повторяется. Если подключён аккумулятор, в событие добавляются `battery_pct` и `battery_v`. При `/heartbeat N` каждые N минут приходит `{"event":"heartbeat", ...}` с полным статусом, как в `/api/status`, плюс `interval_s`.

### MQTT
| Топик | Данные |
|-------|--------|
| `lightwatcher/<id>/state` | `ON` / `OFF` (retained) |
| `lightwatcher/<id>/availability` | `online` / `offline` (LWT) |
| `lightwatcher/<id>/attributes` | JSON как в `/api/status`, раз в минуту и при событиях |
| `lightwatcher/<id>/cmd` | ← команды: `status`, `test`, `restart` |

В Home Assistant через MQTT discovery автоматически появляются сущности: «Електромережа» (binary_sensor, power), «Кількість відключень», «Поточне відключення», «Без світла за 24 год», «Рівень АЦП», а при подключённом аккумуляторе — «Заряд резерву» (%) и «Напруга акумулятора» (В).

Примеры: [`examples/`](examples/) — автоматизации Home Assistant, Python-клиент и приёмник webhook.

## 5. Сборка и обновление с v1.6

1. Arduino IDE → Library Manager: **UniversalTelegramBot** 1.3.0, **ArduinoJson 7.x**, **PubSubClient** 2.8.
2. Tools → Board: ESP32C3 Dev Module, USB CDC On Boot: Enabled, **Partition Scheme: "Minimal SPIFFS (1.9MB APP with OTA/190KB SPIFFS)"** — нужно для OTA. Со старой схемой «Huge APP» прошивка тоже работает, только без OTA.
3. Первый раз прошить кабелем. Настройки Wi‑Fi и Telegram и счётчик отключений сохраняются: ключи Preferences совместимы с v1.6. ⚠️ Смена схемы разделов *обычно* не трогает настройки, но на всякий случай запишите токен бота и chat ID.
4. Написать боту `/adc` при свете и без него и выставить `/threshold` между этими значениями.

## 6. Аккумулятор: подключение и калибровка

АЦП ESP32-C3 точно меряет до ~2,5 В, поэтому напряжение аккумулятора подаётся через делитель:

```
 АКБ (+) ──[ R1 100 кОм ]──┬──[ R2 100 кОм ]── GND
                           │
                        GPIO4 ──┤├── GND   (конденсатор 100 нФ, гасит шум)
```

| Аккумулятор | R1 / R2 | `/bat_div` | `/bat_cells` |
|-------------|---------|-----------|--------------|
| Li-ion 1S (4,2 В) | 100k / 100k | 2.0 | 1 |
| Li-ion 2S (8,4 В) | 300k / 100k | 4.0 | 2 |
| Li-ion 3S (12,6 В) | 100k / 20k | 6.0 | 3 |

Шаги:
1. `/bat_pin 4` — GPIO 0…4, но не пин детектора сети (3). GPIO5 на C3 — это АЦП2, он не работает вместе с Wi‑Fi.
2. Измерить напряжение аккумулятора мультиметром и отправить `/bat_cal 4.05` — прошивка сама поправит коэффициент.
3. `/battery` — проверить.

Как считается прогноз: первую минуту после пропадания сети прошивка ждёт, пока напряжение «сползёт» с уровня зарядки, затем меряет скорость разряда. Прогноз появляется, когда прошло ≥5 минут и заряд упал хотя бы на 2%. При заряде ≤ `/bat_low` (по умолчанию 20%) владелец получает 🪫 с оценкой оставшегося времени, webhook — событие `battery_low`. Кривая разряда — для Li-ion, для LiFePO4 и свинцовых АКБ проценты будут неточными.

## 7. Подписка жильцов

- Любой пишет боту в личку `/subscribe`.
- **Режим «за одобрением»** (по умолчанию): владелец получает «👤 Іван хоче підписатися… /sub_add 123», одно нажатие — и человек подписан.
- **Открытый режим** (`/subs open` или галочка в `/settings`): подписка сразу.
- Подписчики получают те же уведомления, что группа, и могут спрашивать `/light`, `/history`, `/stats`. Админ-команды им недоступны.
- Рассылка идёт порциями по 5 сообщений. Если кто-то заблокировал бота, остальным это не мешает. Лимит — 30 подписчиков; для большего числа лучше группа или канал.

## 8. OTA-обновление прошивки

Нужна схема разделов с OTA (см. раздел 5) — один раз кабелем. Дальше без кабеля:

| Способ | Как |
|--------|-----|
| **Браузер** | Arduino IDE → Sketch → *Export Compiled Binary* → открыть `http://lightwatcher.local/update` (логин `admin`, пароль — ключ из `/web`) → выбрать `.bin` |
| **Arduino IDE по сети** | Tools → Port → *lightwatcher at 192.168.x.x* (пароль — ключ API) |
| **Telegram, удалённо** | Выложить `.bin` по HTTP(S)-ссылке → `/update https://.../firmware.bin`. Устройство скачает, ответит и перезагрузится |

Удобно обновлять устройства на объектах без выезда. Команда `/status` показывает, есть ли OTA-раздел.

## 9. Сервер-агрегатор (Light Watcher Hub)

Один сервер на все устройства: карта и таблица объектов, «есть ли свет» по адресам, отчёт доступности по дням (SLA), CSV, Prometheus, алерт в Telegram «устройство не выходит на связь». Технологии: FastAPI + SQLite, без внешней БД.

**Запуск** (VPS за $4–5/мес или домашний сервер):
```bash
cd server
cp .env.example .env           # вписать LW_INGEST_KEY и LW_ADMIN_KEY (openssl rand -hex 16)
docker compose up -d           # http://<сервер>:8000/
```
Для доступа из интернета поставьте перед ним reverse proxy с HTTPS, например Caddy: `caddy reverse-proxy --from hub.example.com --to :8000`.

**Подключить устройство** (в Telegram-боте устройства):
```
/webhook https://hub.example.com/api/v1/ingest?key=<LW_INGEST_KEY>
/heartbeat 10
```
Объект появится на сервере автоматически, с именем из `/name`. Адрес и координаты задаёт администратор:
```bash
curl -X PATCH https://hub.example.com/api/v1/sites/<device_id> \
  -H "Authorization: Bearer $LW_ADMIN_KEY" -H "Content-Type: application/json" \
  -d '{"title":"Будинок 1","address":"вул. Хрещатик, 1","lat":50.4501,"lon":30.5234,"public":true}'
```

**API сервера** (полная интерактивная документация — `/docs`):
| Метод | Путь | Что |
|-------|------|-----|
| POST | `/api/v1/ingest?key=…` | Приём событий от устройств, повторы игнорируются |
| GET | `/api/v1/sites` | Все объекты: состояние, длительность, без света за 24 ч и 7 дн., заряд |
| GET | `/api/v1/sites/{id}` | Объект + последние отключения |
| GET | `/api/v1/sites/{id}/report?days=30` | По дням: время без света, число отключений, доступность % |
| GET | `/api/v1/sites/{id}/outages.csv?days=90` | Выгрузка для Excel и отчётов арендаторам |
| PATCH / DELETE | `/api/v1/sites/{id}` | Админ: название, адрес, координаты, публичность |
| GET | `/metrics` | Prometheus для Grafana |

**Как сервер справляется с потерей связи:**
- Потерялось событие «свет пропал» → отключение восстанавливается из `outage_duration_s` в событии «свет появился».
- Пульс с другим состоянием, чем на сервере → состояние исправляется.
- Нет пульса дольше 3 интервалов → объект становится «немає зв'язку», в Telegram (если задан `LW_TG_TOKEN`/`LW_TG_CHAT`) уходит один алерт. Когда устройство вернулось — «знову на зв'язку».

Объекты с `public=false` видны только с ключом администратора. `LW_PUBLIC=0` закрывает всё.

## 10. Что проверено, а что нет
- ✅ Прошивка проходит синтаксическую проверку g++ (C++17) с настоящим ArduinoJson 7.2 и заглушками API ESP32.
- ✅ Логика прошивки смоделирована на хосте: дребезг, гистерезис, очередь без Wi‑Fi, длительность и история, тихие часы, восстановление после разряда; разряд аккумулятора 4,2→3,55 В — прогноз и предупреждение «🪫 20%, ~24 хв»; подписка с одобрением и открытая; рассылка 14 адресатам при одном «битом» чате.
- ✅ Сервер: 7 автотестов (pytest) — авторизация, повторы, восстановление потерянного события, пульс и «пропажа» устройства, приватные объекты, отчёт, CSV, метрики. Дашборд проверен в браузере на демо-данных.
- ⚠️ **Прошивка не собрана тулчейном ESP32 и не проверена на железе.** Перед раскаткой: собрать в Arduino IDE и проверить на одном устройстве — вкл/выкл сеть, выключить роутер, перезагрузить без интернета, OTA через `/update`, аккумулятор с `/bat_cal`.
